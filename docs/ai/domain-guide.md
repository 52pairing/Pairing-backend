# Domain Guide (도메인 문서 셀프 가이드)

각 도메인은 자기 문서(`README.md`)를 스스로 만들고 유지합니다.
공통 문서(AGENTS.md, docs/ai/*)는 전 도메인 공통 규칙만 담고,
도메인별 상세(엔티티, 상태, 에러코드, 경계)는 각 도메인 README에 둡니다.

## 왜 나누는가

- 사람과 AI가 매번 전체 문서를 읽지 않고 **공통 문서 + 자기 도메인 README만** 읽게 하기 위함입니다. (토큰 절약)
- 도메인 주인이 자기 도메인을 가장 잘 알기 때문에, 그 문서도 주인이 유지합니다.

## 위치와 담당

- 위치: `src/main/java/com/pairing/{도메인}/README.md`
- 자기 담당 도메인의 README만 만들고 고칩니다. **다른 도메인의 README는 건드리지 않습니다.**
- 이미 있으면 새로 만들지 말고 먼저 읽은 뒤, 작업이 끝나면 갱신합니다.

## 규칙

- 개발을 시작하기 전에 자기 도메인 README를 먼저 읽습니다(있으면).
- 개발이 끝나면 바뀐 부분(엔티티, 상태, 에러코드, API, 경계)을 반영합니다.
- 100줄 안팎으로 짧게 유지합니다. 길어지면 요약하고 상세는 코드나 `docs/spec`으로 미룹니다.
- 실제 값(시크릿, 토큰)은 쓰지 않습니다.
- API 계약이 바뀌면 README가 아니라 `.ai/API.md`를 갱신합니다. README에는 요약과 링크만 둡니다.

## 템플릿

새 도메인 README는 아래 틀로 시작합니다. 해당 없는 항목은 지웁니다.

```markdown
# {도메인} 도메인

## 개요
이 도메인이 책임지는 것 한두 줄.

## 담당자
이름 / 역할.

## 핵심 모델
- 애그리거트 / 엔티티: 역할 한 줄씩.

## 상태
- 상태 enum과 전이 흐름 (있으면). 예: A -> B -> C

## 주요 UseCase / API
- 엔드포인트 요약. 상세 계약은 `.ai/API.md` 참고.

## 에러코드
- `{Domain}ErrorCode` 요약: 코드 - 상황.

## 다른 도메인 경계
- IN: 어디서 들어오는가 (이벤트/호출).
- OUT: 어디로 나가는가 (이벤트/호출).
- 다른 도메인 파일을 직접 고쳐야 하면 먼저 담당자와 사용자에게 말합니다.

## 주의 / 정책 근거
- 헷갈리기 쉬운 규칙, 정책 문서 근거(`docs/spec`) 링크.

## 최근 변경
- YYYY-MM-DD - 요약.
```
